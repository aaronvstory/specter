Who wins where

The scorecard, one axis at a time

Different bets, not the same tool at three quality levels. Specter optimizes for coherence + breadth without a server; byedentity for native depth; GeerGit for per-account rotation in a Flutter shell (all three need root). The one axis byedentity used to own — reads below the Java layer — Specter closed with its Zygisk layer.

Read this as capability, not conquest. These axes measure what each tool changes and how coherently — which is verifiable. None of the three has a proven field-evasion win against a live detector: on-device testing found the dominant re-link anchor is server-side (fuzzy match + a cached ID that survives a wipe), which no client-side spoofer fully touches. Specter leads on capability; "wins in the field" is unproven for everyone here.

Signal-by-signal coverage

What each tool actually changes

A fraud SDK (FingerprintJS-class) computes a deviceId (GSF → mediaDrm → androidId) and a fingerprint — a hash of ~30 hardware/OS signals. Rotating the deviceId is easy; the fingerprint leaks because the physical phone's signals never change. This is the real battlefield.

The finding that changes the standings

byedentity's one structural edge — native-read reach — is now closed

The 2026-07-25 teardown concluded byedentity was ahead on exactly one axis: its boot-time resetprop and Widevine bind-mount sit below the Java layer, so a fingerprinter reading ro.serialno or Widevine via NDK bypassed Specter's Java-only hooks. Specter's Zygisk layer erased that gap.

Before — Java-only hook

A native __system_property_get("ro.product.model") read the real "Pixel 4". Specter's Xposed hook only saw the Java Build.MODEL path. A ~10-prop native blind spot.

→
Now — Zygisk inline hook

The per-app my_prop_get hook intercepts native prop reads. Dual-read probe confirms _java == _native for model, serial, board, fingerprint, baseband, bootloader. 29 spoofed / 0 hard leaks.

Deliberate exception: ro.build.version.sdk and first_api_level are served by a deferred native map (a detached thread flips them ~1.5s after process start) — adding them to the always-on map SIGSEGVs the zygote, since ART/libc read them during init. Proven on-device: read at onCreate = real 30, read after 2.5s = spoofed 29, no crash.

Where byedentity is genuinely deeper — and the plan to absorb it

The goal isn't to beat one detector — it's broad coverage: any user, any check, taking the best of both rivals and going past them. Judged that way, byedentity has real depth Specter should adopt, not dismiss:

  • →Widevine at the native OEMCrypto level. The liboemcrypto.so bind-mount forces a real L1→L3 drop, so an app reading the level through native crypto (below the Java MediaDrm hook) sees it too. Specter's L3 is a Java getter — enough for API readers, not for a native one. Building this (root; Netflix-HD breakage is irrelevant here).
  • →GSF re-registration + app-data wipe. pm clear gms/gsf/vending + reboot resets the Google device identity — this attacks the server-side re-link anchor that on-device testing suggests actually matters. Specter's new "clear data + cache before apply" is step one; GSF-reset is the extension.
  • →Boot-time resetprop as belt-and-suspenders under the Zygisk prop hook — covers a process that reads a prop before the per-app hook attaches.

These are techniques, not a permanent moat — Specter has the root channel to build all three, while keeping the things byedentity gives up: coherence, breadth, US realism, no-reuse, and no server leash.

Per-tool dossier

How each one is built, and where it bleeds

Specter com.specter · 0.13.1

Xposed hooks + Zygisk native layer + a Python reference core. One real device row drives everything; Java↔Python byte-parity keeps generation identical.
  • +Coherence as an invariant. serial↔brand, RAM↔storage↔SoC, DRM id↔level, kernel↔OS, GPU model↔renderer all cross-checked by tests.
  • +Native parity. Zygisk my_prop_get closes the NDK prop blind spot; sensors de-duped; RWX injection pages restored to R-X.
  • +Enforced no-reuse ledger + full US SIM/telephony + both-IMEI spoof.
  • +Stateless. No server — nothing can block or force-update you.
  • −Needs root/LSPosed. Widevine is a Java L3 getter hook, not byedentity's native liboemcrypto bind-mount.

GeerGit Flutter · 2.9.x

Identity generation + persistence live in a Dart AOT libapp.so; a 3-class dex hook just reads it. The Java layer is byte-identical across versions.
  • +Per-account deviceId rotation. Rotates GSF/mediaDrm/androidId per account — the easy half of the problem, done cleanly.
  • −Needs root, same as the others. The dex layer is an LSPosed/Xposed module (five xposedmodule manifest markers) — the "Flutter app" is just packaging; the hook is root-gated exactly like Specter.
  • −Under-spoofs hardware. SoC, baseband, kernel, RAM, Build.* left largely real → the fingerprint hash stays stable → "sometimes detected".
  • −2.9.6 GSF regression. A lazily-cached static (init:_gsf@…, present only in the broken build) reused one fake GSF across signups → cross-account link → coordinated-account bans. Reverted in 2.9.7-beta.
  • −Dart AOT resists decompile — mechanism inferred from symbol diffs + on-device fake-GSF evidence.

byedentity com.byedentity · 3.0.1

Root/Magisk + native-JNI. The native lib builds shell commands; Java runs them as su -c. Startup hard-gates on root + anti-debug + server health.
  • +Native-read depth. Boot service.d resetprop + a Widevine bind-mount that empties liboemcrypto.so to force real L1→L3.
  • +GSF re-registration reset via pm clear gms/gsf/vending + reboot.
  • −Leaves Build.*/SoC/baseband/RAM/IMEI/SIM real — collected into the server payload, not changed. No coherence table.
  • −Server leash. HMAC-signed device report; a 403 blocked deletes local auth, 426 forces an update. The vendor can switch you off.
  • −Several native writes are name-only in the stripped binary — HYP, not readable commands.
Evidence basis & epistemics

How this was read, and how sure we are

Everything above traces to a decompiled artifact or an on-device measurement. Where a claim rests on a native method's name in a stripped binary, it's tagged HYP — not cited as fact.

jadx · dex

byedentity Kotlin/Compose decompiled: the su -c exec helpers, the startup root/anti-debug gate, mount -o bind in the DRM script, and the 15-field HMAC report are literal in the source — PROVEN.

strings · native .so

Serial-mask templates, Frida-artifact probes, and installer messages are literal strings in libbyedentity.so. The native bodies (gen math, exact write commands) weren't disassembled → those stay HYPOTHESIS.

Dart AOT symbol diff

GeerGit's libapp.so can't be fully decompiled. The 2.9.6 ban cause is bracketed by version (2.9.5 clean → 2.9.6 breaks → 2.9.7 fixes) and a symbol present only in the broken build, plus on-device fake-GSF prefs. High confidence on cause, medium on exact mechanism.

dual-read probe

Specter's claims are measured on a real Pixel 4: a native+Java probe reads every spoofable API back. getprop via exec is a false proxy (separate unhooked process); the in-process dual read is the instrument. 29 spoofed / 0 hard leaks.

Honest limits. byedentity's exact native write commands and generation math are inferred from symbol names, not read. GeerGit's Dart mechanism is inferred from symbol/version boundaries. Whether DoorDash's specific SDK reads securityLevel natively, or keys on the fingerprint hash at all, remains a hypothesis — the incoherences fixed are real regardless of which signal any one detector happens to weigh.
