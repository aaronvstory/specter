Specter-iOS · tools, internals & recommendation · 2026-08-04

What actually spoofs a device on iOS — and which of it is worth your time

Mechanism-level internals of the stack you run (RootHide + Crane + SpecterTweak), a blunt try/skip on the other tweaks, and a discovery pass on everything else out there — graded against one target: an app (Cash) that actively inspects itself and likely uses hardware attestation.

The one thing to internalize. On hardened US fintech (Cash / Venmo / PayPal), there is no reliable software spoof — the community's working method is hardware multiplication (one real, un-jailbroken iPhone per account + an OS-level proxy + its own eSIM), the inverse of Specter-on-Android. Two walls cause this: App Attest / DeviceCheck (a Secure-Enclave key that never leaves the chip, verified server-side — unforgeable in software on any device), and a newer one — hardened apps now use a sandbox-escape 0-day (CVE-2025-31207) to enumerate installed app IDs and spot the jailbreak/TrollStore even when hidden (Verichains-confirmed). So the jailbreak itself is a detection risk. Everything below makes the device coherent to passive fingerprinting and buys good multi-account isolation — it does not beat attestation. Decide empirically whether Cash hard-gates on App Attest before investing build time.

01The stack you run — how the three layers fit

Bottom to top, and load order is the whole game (Choicy enforces it):

RootHide — injection substrate + JB-hiding. launchdhook stamps DYLD_INSERT_LIBRARIES → systemhook → PatchLoader → TweakLoader load your dylibs into Cash. Randomizes the jbroot path (no fixed /var/jb) so fixed-path JB probes come up clean. │ Per-app "blacklist" = run an app with ZERO injection (selective absence). Userspace-only: does NOT hide kernel state or App Attest. ▼ Crane — identity + storage layer (the iOS analogue of Specter's set-the-IDs layer). Picks the active container FIRST, │ rebinds container paths, swizzles identifierForVendor, per-container keychain (kSecAttrAccessGroup) + Apple-ID + push token. ▼ Does NOT touch the ~30 hardware/OS composite signals. SpecterTweak — the coherence layer. Hooks what Crane doesn't: sysctl / MobileGestalt / UIDevice / uname / boot-time, keyed to Crane's active container so the composite hash moves WITH the identity instead of pinning to the real SE2/8.
Hard boundary: Crane and SpecterTweak are both in-process hooks in Cash's address space — Cash can see injection is present. You cannot RootHide-blacklist Cash to hide the JB and still spoof it (blacklist = zero injection = Crane + SpecterTweak don't load either). Spoofing requires injection, so JB-hiding inside Cash must be in-process (Shadow), never selective-absence.

02How Crane & RootHide actually work

Crane (opa334, paid)

Crane.dylib is globally injected (early, via ChoicyLoader) and self-gates on per-app prefs; in the target it rebinds app/group/plugin container paths to a container subtree and swizzles identifierForVendor. Privileged work (container CRUD, keychain, push) is brokered out-of-process by the cranehelperd root daemon over XPC, reached via libSandy sandbox extensions. CraneSupport.dylib injects apsd+pkd (per-container push/extensions); the SpringBoard picker is out-of-process. A default-container IDFV change is written to the lsd identifiers cache so it persists unloaded. Uses libundirect to hook objc_direct getters. In-process hooks = detectable; daemons = invisible.

RootHide Dopamine

Rootless iOS 15–16.5 JB whose trait is a randomized jbroot path and per-process injection (no fixed /var/jb, no system-wide dyld patch). launchdhook adds DYLD_INSERT_LIBRARIES→a randomized, unsandboxed systemhook.dylib→PatchLoader(dlopens <binary>.roothidepatch at image-load)+TweakLoader. The per-app blacklist runs a chosen app with no injection at all (stored in a plain editable plist, no GUI needed). Explicitly userspace-only: does not hide kernel state (task_for_pid, sandbox escapes observable) or App Attest.

Real gap this surfaced in SpecterTweak: IORegistry (IOPlatformSerialNumber/UUID, MAC) is an independent read path from MobileGestalt. If SpecterTweak doesn't hook it, the real serial leaks straight through the MG spoof — same lesson as Android's "spoof the field AND its ro.* alias." Also: SpecterTweak's model/serial must match Crane's IDFV-era identity, not a third random device. 04What else is out there — the discovery pass

Everything collapses into three known classes — injection (WeaponX/Specter/Titanox), containers (Crane/LiveContainer), real-device (farms/eSIM) — except one genuinely different architecture:

MobileGestalt on-disk patch family — the standout (Nugget · misaka26 · iEscaper · Picasso). No injection, no jailbreak reliance: it exploits a backup/restore sandbox-escape (SparseRestore/TrollRestore/bookrestore) to rewrite the device's own com.apple.MobileGestalt.plist cache, so every process reads a coherent, changed hardware identity at the OS source — the inverse of per-app injection, and inherently coherent. Crucially for your case: nothing is injected into Cash → nothing in Cash's image list to detect. Limits: it's device-wide (one identity for the whole phone, no per-app rotation), covers MG hardware keys only (not IDFV/IDFA/serial — those live in keychain/IOKit), and the delivery exploit is patched on iOS 26.2+ (works on your 16.3.1; family spans iOS 15–26.1). Best use: the device-wide hardware-coherence layer *under* Specter's per-app injection — the closest thing to Specter-Android's BOARD/HARDWARE/composite alignment. Repos: leminlimez/Nugget, GeoSn0w/iEscaper (widest range), straight-tamago/misaka26, Rust505/autoPatcher-mobilegestalt (the raw patch engine).

Titanox watch

No-JB in-app hooking framework (fishhook + MemX) that ships inside a TrollStore/sideloaded app. Same hooking class as Specter, but a non-jailbreak distribution path. Not needed on RootHide now; the future-proofing lever when the JB ceiling drops. Ragekill3377/Titanox, MIT.

fingerprintjs-ios + trustdevice-ios read first

The two leading open-source iOS fingerprinting libraries — i.e. the exact spec of which signals a spoofer must cover and where the coherence traps are (IDFV must survive reinstall, IORegistry must match the claimed model). Highest-leverage zero-cost item — read before writing another hook.

Dead ends (don't chase): LiveContainer for anti-linking — its container/keychain isolation regressed in 2026 (issues #1443/#1154) and all guests share one signing cert (a stable cross-account signal); anti-detect "browsers" (web fingerprints, irrelevant to native attestation); emulator/Simulator (no Secure Enclave → instant attest fail); farmed/replayed attest tokens (dead vs any nonce+timing backend).

05The ranked shortlist — what to actually do

  1. Read fingerprintjs-ios + trustdevice-ios source — zero cost, defines the exact signal set + coherence traps. Before any more hooks.
  2. Read ProjectX (WeaponX) source — the reference iOS Specter; lift its per-app scoping + IORegistry hooks, close SpecterTweak's IORegistry gap. Don't run it alongside.
  3. Install Choicy (opa334's repo) — Deny-mode Cash to Crane + SpecterTweak (+ Shadow). Enforces load order + one-engine-per-app. Non-negotiable.
  4. Keep Crane — per-app container + separate keychain is the real multi-account isolation. Do not switch to LiveContainer (isolation broken in 2026).
  5. Try Nugget / iEscaper on 16.3.1 — apply a coherent device-wide MG hardware change as the layer beneath per-app injection. Device-wide MG truth + injection for per-app IDFV/IDFA. The nearest thing to Specter-Android's composite alignment, and it's invisible to Cash's image scan.
  6. Shadow — optional in-process JB-hider for Cash; backstop only.
  7. Titanox — later, only if you want a no-JB sideload distribution path.
Reality check on the target. If Cash enforces App Attest server-side, none of 1–7 wins — the JB itself is flaggable and the Secure Enclave can't be faked. Items 1–5 make the device coherent to passive fingerprinting and give good multi-account isolation; the only thing that holds against attestation is a real un-modified iPhone per account. The decisive next experiment is empirical: does injecting into Cash (even an inert dylib) change its behavior, and does Cash actually gate on attestation? See docs/ios/DETECTION-EXPERIMENT.md.
