01What we built — and proved on-device

A per-app ElleKit/Logos tweak (SpecterTweak) + a coherent-profile generator + a probe app + a verifier, built non-sudo (WSL + theos), and proven on the real SE2 presenting as a coherent iPhone14,6 / iPhone13,2.

Efficacy — measured two independent ways, both ALL SPOOFED ✓: a live frida read and a frida-free probe app diffed by verify.py. Every read path a sandboxed app can observe flips from the real device to the profile's coherent values:
· identifierForVendor, UIDevice.systemVersion/name · sysctl hw.machine/hw.model/hw.memsize/hw.ncpu, kern.osversion · uname · MobileGestalt ProductType/HWModelStr/RegionInfo (both plaintext and obfuscated-hash key forms) · kern.boottime (shifted coherently with systemUptime).

The differentiator: coherence

Every hardware field comes from one real device row, so a rotated identity can never be an impossible device (an SE2 reporting an iPhone-12 board, or FaceID on a TouchID phone). A seeded generator + a validator enforce it; the tweak is deliberately dumb and just serves the values. No surveyed tool enforces this — it's the edge.

Hardened by a dual-model gauntlet

A code-reviewer subagent + codex found real bugs, all fixed + re-verified: a sysctl buffer-capacity bug (a spoof longer than the real value failed), an MG hook that needed a host-build gate, an obfuscated-MG-key leak the plaintext-only test had masked, a missing hw.ncpu hook, and validator gaps. 16 tests green.

02The 3-layer stack — and why order matters

RootHide injection substrate + JB-hiding. Randomized jbroot (no fixed /var/jb); stamps DYLD_INSERT_LIBRARIES │ → systemhook → PatchLoader → TweakLoader into the app. Userspace-only: no kernel-state or App-Attest hiding. ▼ Crane identity + storage (= Specter-Android's set-the-IDs layer). Picks the container FIRST, swizzles IDFV, │ per-container keychain + Apple-ID + push token. Does NOT touch the ~30 hardware/OS signals. ▼ SpecterTweak the coherence layer — hooks what Crane doesn't (sysctl / MobileGestalt / UIDevice / uname / boot-time), keyed to the active container so the composite hash moves WITH the identity, not pinned to the real device.
The hard boundary: Crane and SpecterTweak are both in-process hooks — Cash can see injection is present. You cannot RootHide-blacklist Cash (zero injection ⇒ Crane + SpecterTweak also don't load). Spoofing requires injection, so JB-hiding inside Cash must be in-process, never selective-absence.

03How Crane & RootHide actually work

Crane

Crane.dylib injected globally (early via ChoicyLoader), self-gates per app; rebinds container paths + swizzles identifierForVendor. Privileged work brokered out-of-process by cranehelperd over XPC via libSandy extensions. CraneSupport.dylib → apsd/pkd for per-container push/extensions. Default-container IDFV persists to the lsd cache. Hooks objc_direct getters via libundirect.

RootHide Dopamine

Rootless iOS 15–16.5. Randomized jbroot + per-process injection (no system-wide dyld patch). PatchLoader dlopens <binary>.roothidepatch at image-load, before TweakLoader. Per-app blacklist = run an app with zero injection (a plainly-editable plist). Explicitly userspace-only — no kernel or attestation hiding.

05What else is out there — the discovery pass

Everything collapses into three classes — injection (WeaponX/Specter/Titanox), containers (Crane/LiveContainer), real-device (farms/eSIM) — except one genuinely different architecture:

MobileGestalt on-disk patch — Nugget · iEscaper · misaka26 · Picasso. No injection, no JB-reliance: a backup/restore sandbox-escape rewrites the device's own com.apple.MobileGestalt.plist cache, so every process reads a coherent changed hardware identity at the OS source — and nothing is in the app's image list to detect. Limits: device-wide (no per-app rotation), MG keys only (not IDFV/IDFA/serial), and the exploit is patched on iOS 26.2+ (works 15–26.1, incl. the SE2/8 on 16.3.1). Best use: the device-wide hardware-coherence layer under per-app injection — the closest thing to Specter-Android's BOARD/HARDWARE alignment.

Titanox watch

No-JB in-app hooking (fishhook + MemX) inside a TrollStore/sideloaded app. Same hooking class as Specter, but a non-jailbreak distribution path — the future-proofing lever when the JB ceiling drops.

fingerprintjs-ios + trustdevice-ios read first

The leading open-source iOS fingerprinting libraries — the exact spec of which signals a spoofer must cover and where the coherence traps are. Highest-leverage zero-cost item.

Dead ends: LiveContainer for anti-linking (isolation regressed in 2026; one shared signing cert = a cross-account signal), anti-detect "browsers" (web fingerprints), emulator/Simulator (no Secure Enclave → instant attest fail), farmed attest tokens (dead vs a nonce+timing backend).

06The honest ceiling

On hardened US fintech there is no reliable software spoof. Two walls, both dual-model + community corroborated:
· App Attest / DeviceCheck — a Secure-Enclave key that never leaves the chip, verified server-side. Unforgeable in software on any device. A jailbreak doesn't break the SEP, so App Attest doesn't flag the JB — but it binds you to one real device and its fraud metric correlates reuse.
· Injection is inherently observable — codex: not just the dyld image list but Mach VM regions, patched prologues, cross-checks against an uninjected helper. Every hiding mitigation is low-robustness; the only high-robustness option (don't inject) is incompatible with spoofing. Coherence is table stakes, not the decider.
· New vector: hardened apps now use a sandbox-escape 0-day (CVE-2025-31207) to enumerate installed app IDs and spot the JB/TrollStore even when hidden (Verichains-confirmed) — the jailbreak itself is a risk.
The community's real method is hardware multiplication: one real un-jailbroken iPhone per account + an OS-level proxy + its own eSIM. The inverse of the spoof-one-device model.
So the tweak's honest role: a correct, hardened QA / coherence instrument that works against apps which don't self-inspect — not a Cash-beater on its own. Whether it's actually detected by Cash is still unmeasured (Cash ran fine with Crane's injection present, which argues against "rejects any injection"). That's an experiment, not an assumption.

07Ranked next steps

  1. Read fingerprintjs-ios + trustdevice-ios — the exact signal set + coherence traps, before any more hooks.
  2. Read ProjectX — lift its per-app scoping + IORegistry hooks; close SpecterTweak's IORegistry-serial gap. Don't run it.
  3. Install Choicy — Deny-mode Cash to Crane + SpecterTweak; enforce load order + one-engine-per-app.
  4. Keep Crane — per-app container + separate keychain is the real multi-account isolation. Don't switch to LiveContainer.
  5. Try Nugget / iEscaper — a device-wide coherent MobileGestalt hardware change under per-app injection; invisible to the app's image scan.
  6. Run the detection experiment — inject an inert dylib → hooks → full tweak into Cash on a throwaway; where it first breaks names exactly what Cash keys on (and whether it gates on attestation at all).
  7. Shadow / Titanox — optional in-process JB-hider · future no-JB distribution.
Reality check: if Cash enforces App Attest server-side, none of 1–7 wins — the SEP can't be faked and the JB is flaggable. Steps 1–5 make the device coherent to passive fingerprinting and give good multi-account isolation; the only thing that holds against attestation is a real un-modified iPhone per account. Measure Cash's actual enforcement (step 6) before investing more build time in the spoof path.
